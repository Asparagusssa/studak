# Проверка Telegram-бота — 18 ноября 2026

## Результат

- 8 Telegram-тестовых функций с вложенными проверками, включая полный пользовательский путь.
- Весь Go-набор — три прогона без ошибок.
- Telegram- и MAX-тесты — пять прогонов на отдельной PostgreSQL-базе.
- go test -race ./... и go vet ./... — успешно.
- Публичный /health отвечает 200; Telegram подтвердил текущий webhook, очередь обновлений пуста, ошибки доставки не сообщаются.
- Публичный /webhook/tg: без секрета — 401, неизвестный допустимый update — 200, сломанный JSON — 400.
- Отдельная база тестов удалена. Рабочие анкеты для тестовых лайков, сообщений или удаления не использовались.

## Исправление

Описание связи User.PreferredUniversities дополнено каскадным удалением, чтобы создаваемая GORM тестовая схема соответствовала SQL-миграциям PostgreSQL. Удаление анкеты с выбранными вузами проверено повторно на обеих СУБД.

## Аккаунты и окружения

Оба бота используют одну таблицу users и общую базу лайков/мэтчей. TelegramID и MaxID независимы. Совпадение числовых ID не объединяет людей. Регистрация одного человека в двух мессенджерах сейчас создаёт две анкеты; привязки для объединения аккаунтов нет. Локальная база и база будущего хостинга — разные окружения, для сохранения анкет потребуется перенести PostgreSQL.

Фотографии из Telegram хранятся как file_id и показываются в Telegram; токены фото MAX — в MAX. Единое медиахранилище ещё не подключено.

## Что не проверено автоматически

Отображение в настоящих Telegram-клиентах iOS/Android и фактическая доставка фото/сообщений между двумя живыми аккаунтами. API-отправки в сценариях имитируются; реальный webhook и регистрация проверены отдельно. Нагрузка с сотнями пользователей не имитировалась.

Автоматической очереди исходящих сообщений пока нет. Тайм-аут после фактического принятия сообщения Telegram может оставлять неоднозначный результат. Проверки повторов не являются гарантией доставки ровно один раз при любом сетевом сбое.
