# Проверка локальной «Искры» — 18 ноября 2026

Проверен Go-бэкенд Studak, обслуживающий MAX. Рабочая анкета не использовалась для тестовых лайков и сообщений. PostgreSQL-тесты выполнялись в отдельной временной базе; после проверки она удалена.

## Результат

- 24 тестовые функции, включая вложенные сценарии. Полный набор Go-тестов прошёл три повторных прогона.
- MAX-сценарии прошли пять повторных прогонов на PostgreSQL, включая одновременные встречные лайки и блокировку, пришедшую вместе с лайком.
- go test -race ./... и go vet ./... — успешно.
- Совокупное покрытие Go-кода тестами: 63,7%. Это не показатель процента отсутствующих ошибок.
- Все семь SQL-миграций успешно применены в отдельной базе.
- Локальный бэкенд обновлён, /health и зарегистрированный HTTPS-туннель отвечают 200.
- Webhook без секрета отклоняется (401), некорректный JSON с верным секретом — 400, допустимое неизвестное событие — 200.
- REST API без учётных данных отклоняется (401). Подписка MAX указывает на текущий /webhook/max.

## Сценарии

Регистрация и продолжение после /start; некорректный ввод; выбор вузов; сохранение фильтров без перезаписи анкеты; поиск по полу; одно фото, отказ от нескольких изображений, пропуск, замена, удаление и резервный показ карточки при ошибке вложения.

Входящий лайк, взаимность, пропуск и старые кнопки; список мэтчей; текстовое сообщение и ответ; отмена; недоступность переписки до мэтча и после разрыва; защита от повторной пересылки одного сообщения.

Пауза и возврат; сохранение старой переписки на паузе; блокировка в обе стороны, снятие блокировки без восстановления мэтча; отмена удаления, старое подтверждение и окончательное удаление связанных лайков/блокировок.

Групповые сообщения и кнопки; ошибочный секрет; пустой, некорректный, слишком большой и пакетный webhook; отказы MAX API; параллельная доставка одного события; повтор события после создания нового экземпляра бота.

## Исправлено в ходе проверки

1. Ответы MAX success: false и повреждённый JSON больше не считаются успешной отправкой.
2. Кнопки из группового чата и события от ботов не меняют личную анкету.
3. События одного пользователя обрабатываются последовательно. Идентификаторы успешно обработанных событий хешируются и сохраняются на семь дней; повторное событие не двигает регистрацию заново. Для этого добавлена миграция 00007_max_webhook_dedup.sql.

## Границы проверки

Настоящие отправки сообщений и фотографий двум пользователям MAX не выполнялись. Доставка проверена через тестовый MAX API, публичный webhook — отдельно. Фактическое отображение на iOS/Android остаётся для ручной проверки.

Проверка гонок внутри процесса не доказывает корректность всех распределённых ситуаций. Локальная сериализация событий рассчитана на один экземпляр бэкенда. Для нескольких реплик потребуются распределённая очередь/блокировка.

Единой транзакции между PostgreSQL и API MAX нет. Сбой между обновлением состояния и отправкой либо тайм-аут после принятия сообщения MAX остаются неоднозначными. Это не гарантия доставки ровно один раз; полноценная очередь исходящих сообщений с разбором статусов пока не реализована.

Нагрузочный тест с сотнями реальных пользователей, аудит хостинга и визуальная проверка старого React-фронтенда в эту проверку бота не входили.
