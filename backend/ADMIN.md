# Управление Студаком

## Доступ администратора

Отправьте `/id` в личном диалоге с каждым ботом. Команда доступна и без анкеты.
Добавьте числовые ID в `backend/.env`, например:

```dotenv
ADMIN_TELEGRAM_IDS=123456789
ADMIN_MAX_IDS=987654321
```

Несколько ID разделяются запятыми. Списки Telegram и MAX независимы; пустой список
не даёт доступ никому. Username и контакт анкеты не дают прав администратора.
После изменения `.env` пересоздайте backend, например повторным запуском
`./start-ngrok.sh` из `backend` (работающий туннель будет использован повторно).

Команда `/admin` открывает админку даже до создания собственной анкеты. У
администраторов в главном меню также появляется кнопка «Админка».

В админке доступны общий счётчик регистраций, разбивка по платформам, список всех
готовых анкет с постраничной навигацией, блокировка и разблокировка пользователей,
сброс пропусков для одного пользователя или всех, запуск знакомств. Действия с
изменением данных требуют одноразового подтверждения. Администратора из любого
настроенного списка нельзя заблокировать.

Административная блокировка скрывает анкету и запрещает пользоваться ботом, в том
числе удалить и заново создать анкету с тем же аккаунтом. Анкета остаётся в базе.
После разблокировки её снова можно использовать. Личные блокировки между
пользователями остаются отдельной функцией.

Сброс пропусков удаляет только исходящие отрицательные реакции выбранного
пользователя (или всех пользователей). Обычные лайки и личные блокировки
сохраняются. Пропущенные анкеты снова могут появиться с учётом остальных фильтров.

## Отложенный запуск

Миграция `00011` создаёт в базе флаг **знакомства ещё не запущены**. До запуска
доступны регистрация, своя анкета и настройки. Лента, реакции, входящие лайки и
старые кнопки мэтчей закрыты. Ограничение действует также на REST-ленту и реакции.
Кнопка «Запустить знакомства» с подтверждением открывает знакомства сразу в
Telegram и MAX. Флаг хранится в базе и переживает перезапуск; повторный запуск
контейнера не закрывает знакомства снова. Автоматической рассылки при запуске нет:
пользователи открывают ленту из меню.

## Счётчики

В приветствии и главном меню показываются все зарегистрированные анкеты и число
анкет текущего мессенджера. Это число готовых анкет, а не начатых регистраций;
один человек с двумя анкетами в разных мессенджерах считается дважды.

При поиске и выборе вузов/колледжей кнопка показывает число зарегистрированных
в этом учебном заведении в текущем мессенджере. Анкеты на паузе включены,
административно заблокированные исключены. Собственная анкета также включена.
Число регистраций не равно размеру ленты: возраст, пол, выбранные вузы,
предыдущие лайки, пропуски и личные блокировки влияют на выдачу отдельно.

## Взаимные симпатии без списка мэтчей

Раздел «Мои мэтчи» удалён. После взаимности каждый получает сообщение с контактом;
оно остаётся в переписке. Старые кнопки не раскрывают контакт повторно.

Взаимные лайки хранятся только до успешной доставки сообщений обоим людям, затем
обе строки удаляются. При сбое мессенджера фоновая задача повторяет недоставленные
сообщения каждые 15 секунд, в том числе после перезапуска. Уже подтверждённая
доставка повторно не отправляется; авария между отправкой и фиксацией в БД всё же
может привести к повторному сообщению, поскольку API мессенджера и БД не образуют
общую транзакцию. Постоянной истории мэтчей нет, поэтому пара может снова попасть
в ленту и снова получить взаимность. При административной или личной блокировке
недоставленная взаимность удаляется.

Миграция `00012` удаляет прежние взаимные лайки из базы; сообщения в мессенджерах
сохраняются. Невзаимные лайки, пропуски, пользователи и личные блокировки сохраняются.
